# 代码审查

1. 找出改动：`git status` 和 `git diff`（已暂存的看 `git diff --cached`，某个提交看 `git show <提交>`）。新文件直接读全文。
2. 读每处改动附近的代码，弄清这处改动想做什么、谁会调用它。
3. 只报告真实的问题，每个问题都要说清楚：在什么输入或情况下出错、错成什么样。重点看：
   - 逻辑和边界：空值、空列表、越界、除以零、编码、时区。
   - 异常没处理、文件或网络连接没关闭、超时和重试。
   - 改了函数，调用它的地方没跟着改。
   - 密钥、token、密码写进了代码、日志或提交里。
4. 能验证的就验证：`python3 -m py_compile <文件>` 检查语法，`python3 -m unittest discover -s tests` 跑测试。
5. 回复：先用一句话说能不能提交，再按严重程度列问题（文件:行号、问题、怎么修）。没有问题就直说没有，不要凑数。
6. 用户没让你改，就只报告，不要动代码。
